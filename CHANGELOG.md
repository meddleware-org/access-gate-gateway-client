# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.0.21] - 2026-10-24

### Changed

- **Breaking:** the access message domain is `access-gate-gateway:access:v3` (was `nft-gate:access:v2`; ADR-0004). The audience lines are unchanged; a v2 proof is refused by the gateways. `vectors.json` regenerated.

## [0.0.20] - 2026-10-24

### Changed

- The package keyword is `access-gate-gateway` (workspace naming convention, ADR-0003). No code change.

## [0.0.19] - 2026-10-24

### Changed

- Renamed from `nft-gate-client` to `access-gate-gateway-client` (workspace naming convention, `docs/architecture/ADR-0003-naming.md`). No code change beyond names, paths, hostnames and dependency names; the history below keeps the old names.

## [0.0.18] - 2026-10-22

### Changed (breaking for lenient callers: a few digests that 0.0.17 accepted are now refused)

- `isTransactionDigest` (and so `personalMessage`, `encodeAccessProof`, `decodeAccessProof`) requires a
  base58 string that decodes to exactly 32 bytes, not just 32-44 base58 characters. A leading `1` counts as
  a zero byte; 43 characters can be 31 bytes and 44 can be 33. `nft-gate-core` (`is_tx_digest`) applies the
  same rule.
- `buildAccessProof` checks the `address` (`0x` + 1-64 hex digits) and the challenge's expiry before asking
  the wallet to sign, so the user is never prompted for a proof a gateway would refuse. A challenge is
  expired once the local clock is more than `CHALLENGE_CLOCK_SKEW_MS` (30 s) past `expiresAt`.
- `fetchChallenge` sends `cache: 'no-store'` and `credentials: 'omit'` (redirects were already refused).
- `GATEWAY_STATUS` gains `methodNotAllowed` (405) and `loopDetected` (508), which the gateways already emit.

### Added

- `vectors.json` `txDigest` (valid and invalid digests: 32/43/44/45 characters, leading `1`s, `0 O I l`),
  five digest cases in `proofDecodeRejects` and two in `personalMessageRejects`.
- `vectors.json` `responses`: the status and `{ error, code? }` body each gateway answers for sixteen
  outcomes (missing or bad proof, each denial, rate limit, loop, `redeemed` / `leased` conflict, commit
  failure, lost lease, store outage). Both gateways map every outcome to a stimulus of their own.
- `CHALLENGE_CLOCK_SKEW_MS` export.
- Tests: a real local HTTP server that answers 302 / 301 proves the redirect is refused and never followed;
  signer spies prove the wallet prompt is not reached on a bad address or an expired challenge.

## [0.0.17] - 2026-10-10

### Changed (breaking for lenient callers: a few tokens that 0.0.16 accepted are now refused)

- `decodeAccessProof` is strict at the base64, UTF-8 and JSON layers and makes the same decisions as the
  Rust gateway (`gateway-rust/src/proof.rs`). It refuses an unpadded token, whitespace or `=` inside the
  token, the URL-safe alphabet, non-zero trailing bits, invalid UTF-8 (also inside an unknown key), a
  byte-order mark, JSON nested more than 127 levels, an unpaired surrogate `\u` escape and a number that
  overflows (`1e999`). Whitespace at either end of the token is still ignored, as `trim()` does in Rust.
  Every token `encodeAccessProof` emits is canonical and round-trips.
- `gatewayOrigin` no longer echoes the gateway string in its errors (it may carry userinfo).
- `engines.node` is `>=24`.

### Added

- Eleven `proofDecodeRejects` vectors in `vectors.json` for the layers above, so both gateways' suites pin
  the strict behaviour.

### Fixed

- Narrowing casts at trust boundaries (`challenge.ts`, `proof.ts`, `contract.ts`) are replaced by type
  guards; no `as` remains in `src/` outside `as const`.

## [0.0.16] - 2026-10-08

### Changed (breaking: protocol v2, no v1 compatibility)

- The signed message is now `nft-gate:access:v2`, multi-line ASCII binding the gateway **origin**,
  the **gate** id, the **network**, the nonce and (single-use gateways) the consume digest. A
  signature made for one gateway, gate, network or consume cannot be replayed at another. Gateways
  rebuild the message from their own configuration. `personalMessageForNonce` is replaced by
  `personalMessage(context)`; `buildAccessProof` takes `gateway`, `gateId` and `network`.
- `encodeAccessProof` applies the same rules as `decodeAccessProof` (address `0x` + 1-64 hex, nonce
  `[A-Za-z0-9._~-]{1,128}`, base64 signature, base58 consume digest), so a token this package emits is
  one every gateway accepts.
- `fetchChallenge` refuses redirects, caps the body while streaming (4 KiB) and requires a camelCase
  `expiresAt` that is a positive number and a nonce in the challenge alphabet (no snake_case fallback).

### Added

- `vectors.json` (`@meddleware/nft-gate-client/vectors.json`): the conformance vectors both gateways
  test against, generated by `scripts/gen-vectors.mjs` with real signatures (ed25519, secp256k1,
  secp256r1, single-use) plus audience-mismatch, negative-signature, ZIP-215 and token-grammar cases.
- `personalMessage`, `gatewayOrigin`, `isNonce`, `ACCESS_MESSAGE_VERSION`, the `SuiNetwork` and
  `AccessMessageContext` types, and the gateway response contract (`GATEWAY_STATUS`,
  `GATEWAY_CONFLICT_CODES`, `parseGatewayError`).

## [0.0.15] - 2026-10-03

### Changed

- `"sideEffects": false` in `package.json`: the package has no import-time side effects.
- Built with `noUncheckedIndexedAccess` (no API change).

## [0.0.14] - 2026-10-02

### Changed

- `fetchChallenge` aborts after `timeoutMs` (default 10 s) as well as on the caller's `signal`, so a
  hung gateway no longer stalls an upload. The host must be `https:` (`http:` only for a loopback
  host) and the URL is built with `new URL` (a path prefix is kept; query and fragment are dropped).
  The response is size-capped (4 KiB) before parsing; `nonce` must be a non-empty ASCII string and
  the expiry a finite number.

## [0.0.13] - 2026-09-30

### Changed

- **Breaking:** the package is now the nft-gate **wire protocol only** — `fetchChallenge`,
  `personalMessageForNonce`, `buildAccessProof`, `encodeAccessProof`, `decodeAccessProof`,
  `isTransactionDigest` and the `Challenge` / `AccessProof` / `PersonalMessageSigner` types. Every
  `access_gate` PTB builder, read and object type moved to `@meddleware/access-gate-client`
  (no re-exports).
- No runtime dependencies (`@mysten/sui` removed).

### Added

- `isTransactionDigest(s)`; `buildAccessProof` rejects a `consumeDigest` that is not a base58 Sui
  transaction digest (before asking the wallet to sign).

### Added
